# 作者反馈应用

保留技能名以兼容已有调用；本技能提供通用方法，不内置私人项目剧情、人物或路径。

## 使用方式

1. 确认这轮正文版本、修改范围、作者最新明确决定及相关反馈。历史案例只解释当时问题，不能覆盖后来决定。
2. 判断反馈属于事实修正、作者偏好、特定场景要求还是暂定方案。只应用与当前场景相关的部分；没拿到反馈时不声称知道作者习惯。
3. 检查信息、时间、空间、动机等可信度，也检查情绪、关系、节奏和故事实际变化。基本合理不能替代阅读吸引力，审查顺序不代表后者可跳过。
4. 给出有位置和证据的最小修正。未获改稿授权时只交意见；不把候选建议写进公共设定。

## 防止反馈过度泛化

- 第一人称信息边界按作品叙述方式判断，不要求每次推测都加固定句式。
- 关键物件和动作要有必要来源，不逐笔复述取得、交接、保管；已有清楚信息可直接承接。
- 空间和流程只补到读者能理解关键选择。现实事实不足时标明待核，不用想象的程序拖长故事。
- 普通人的犹豫、代价和悲伤要与关系及情境相符，不把哭泣、拒绝、拍照或记笔记设成每章动作。
- 细节够用即可，不规定材质数量、固定景别或统一句长；对白也可以修复关系、试探或自然留白。
- 恐怖、紧张或快节奏要求只用于相应场景。安静戏、过渡和亲情戏可以承担恢复、对比、关系变化，不能为了合规硬加灾祸。
- “有下一步”不足以证明推进。比较相关前文，看调查结果、判断、人物处境、关系或读者认识是否发生实质变化；重复申请仅换日期和编号应合并或调整。

## 审查输出

先标明读到的版本与范围、采用了哪些具体作者决定；再按必须改、建议改、待核实列出证据、影响和修正方向。个人偏好注明适用场景，不包装成普遍硬伤。作者设定核对与冷读体验分开；看过私有答案的审查不能伪称盲读。

默认不评分；若用户要求，依据具体正文和明确标准评分，不替另一审查者生成结论。自查如实标为自查，不签发独立通过或续写权限。新版本不继承旧版本审查。

复杂反馈归纳可参考 [通用改稿模式](references/revision-patterns.md)，不必每次全读或另建台账。
