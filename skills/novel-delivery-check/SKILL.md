# 指定版本交付核对

确认本次验收对象、版本、阶段和作者已经约定的完成条件。方案可以验证可拆章性，正文才能验证实际阅读效果；阶段结论不得外推为整书完成或作者认可。不要自行加分数门槛、固定章数或新增一层审查。

## 先核对真正提交了什么

- 找到指定文件并读取实际内容，不用同名旧版、最新时间或“最终版”文件名代替。缺目标稿时结论为“材料不足／未验收”，不是内容不合格，也不自行生成一份稿来补齐。
- 读取当前约定要求且已存在的审查返回及必要承接。报告必须对应指定版本与范围；旧版报告可帮助定位问题，不能直接迁移分数。改版后按影响复查，不重复整套未受影响检查。
- 核对实际审查来源：任务已发送、已收到、审查角色文件夹和主笔自填身份都不能证明报告已返回。若要求的审查缺失，说明具体缺口；自己完成委托内的核对，不把任务循环转回自己或主控。
- 本次核对不自动等于独立冷读。用过作者真相或其他报告的上下文要如实标明，不能把知情验收称成首次盲读。

## 处理问题而非只看结论词

对已有必须修改项，核对是否在本版实际解决，并记录新增冲突。分别处理：

- **当前阻断或应修**：已损害当前因果或阅读体验，且项目约定要求先解决。写“需修订／尚未通过”，不能同时宣布“已通过”；“小修后可通过”只是条件预测，修后还需核对相应变化。
- **必要材料缺口**：无法确认版本、来源或关键现实依据。说明哪些结论尚不能成立，不补造证据。
- **下一阶段承接**：当前章节可以有完整作用，某项行动反馈需在后文兑现。与当前缺陷分开，记录承诺和兑现时机；不以“以后再说”掩盖已影响本章的缺口，也不要求提前公开所有谜底。
- **可选建议**：偏好、局部措辞或未造成实质影响的优化。不把它们升级为永不结束的返工门槛。

分数与正文证据冲突时先澄清。既有硬性分数条件按项目执行，但高分不能覆盖未解决问题，逻辑成立也不能抹掉阅读质量问题。不改分凑门槛、不额外找审查者直到有人同意。

## 给出可用的阅读入口

在已有进度中说明当前候选版本、审查状态、供阅读版本及真实剩余项；保留上一版已通过记录，不能把修改后的待审稿静默替换进去。作者明确认可另列，不把助手验收当作者签字。

输出以“对象和实际已读范围 → 已满足条件 → 尚未解决或待补事项 → 本阶段结论”为宜，附必要位置证据即可。能交付且只剩建议时明确收束；缺材料时只请求真正缺少的材料，不开启额外评审组织。

交付结论本身不是下一批授权。仍要遵守当前批次、修订与运行边界；不自动派发、暂停现有任务、发布或改正文。用户已要求相关操作时按具体范围执行，不再重复询问既有授权。
