# 协作规则：以真实结果决定是否继续

本文件适用于已授权的多人/多代理小说任务，不自行授予跨聊天消息、外部发布、费用或数据访问权限。简单任务直接完成；独立任务需要实际收益才委派，不机械建立更多角色。

技能按实际任务选择，不要求每章运行全部技能。维护、排查、发布准备和既有工作流追问不必反复重新选工具；宿主有额外路由要求时遵从该要求，但推荐权重只用于匹配，不能证明技能实际使用、审查质量或额外操作已获授权。最高推荐结果与当前目标不符时，不据此转向安装、下载或开发另一套系统。

## 最小职责分离

主笔产出正文和自检；独立审稿产出自己的判断；主控负责核对返回、处理分歧及交付。允许主控原样保存审查者的真实返回，但不允许主笔预制整套通过报告，再把角色文件名当成独立性。

没有独立执行能力时可以做明确标注的自检，不能声称已经完成独立审查；若项目要求独立审查，应保存待审稿，报告缺口。独立代理并非天然正确，同模型、共享上下文和同一提示偏差仍可能造成共同误判。

一次委派只需说明输入版本、阅读范围、目标、允许写入范围及返回内容。审稿不看旧分和“必须过关”的暗示；冷读不看谜底，逻辑检查按需看设定。指定文件版本提交后不在原文件偷偷修改。

## 主控需要核对的内容

1. 本次审查确实返回，而非只有一个叫“审查报告”的文件；核对可访问的执行来源，不接受主笔自填字段作为独立证据。
2. 报告与指定正文版本一致；引用的细节真实存在，结论与证据相称。来源记录是定位信息，不是可自动信任的认证签名。
3. 未解决阻断/应修问题是否处理；分数、草稿状态与正式认可分别记录。
4. 当前单元是否有所兑现；连续推进是否仍在授权范围和约定预算内。

主控不需要每次另建审核表或让用户逐章签字。把必要依据写在现有报告与进度中；对异常样本定向回读即可。

跨技能交接保留问题的实际严重度：旧称“必须改”须说明是当前单元因果失效的阻断，还是局部应修；偏好优化是建议。待核实说明影响范围，不一律升级为阻断，也不能借换标签降低真实问题。是否进入下一步仍由当前项目的准入条件决定。

## 状态与调度

建议最小状态：草稿待审 → 审查中 → 需要修订 / 可交付 → 已交付。作者认可单独记录，不能由分数自动生成。

在已有进度入口维护候选版本、审查状态和供阅读版本路径，不另造多套重复台账。最高版本号、最新时间和“最终版”文件名不代表通过。交付正文应说明其状态；修改通过稿后，原通过记录仍指向旧版，新版先标待审，不能静默替换。

一个执行回合只能有一个下一步调度者。按章节、正文版本和当前阶段识别同一工作；正在执行或已发送未返回时不重复派发，不向自己递归发继续。轮询只用最小状态，没变化不重复叙述。

新增章数与修订轮数默认不设固定上限；实际范围以作者授权为准，明确约定的投入边界继续有效。新章先对照上一章适用版本和当前单元内相关前文，修订再对照同章上一稿与未解决意见；必要时定向回读更早的相关段落，不每轮全书重读。新内容应在人物处境、认知、关系、选择、证据、行动后果或局部答案上有实际作用，修订应实际改善具体问题。仅换日期、地点、名字或措辞，反复查询/等待、重复同一悬念而没有新后果，或同一问题来回改无改善，都不能靠高分变成继续依据。伏笔回收、情感深化、必要过渡及有新后果的重访不能只因元素复现被判重复。

有具体未解决问题、可执行处理方向且仍有实质改善时，可以在授权范围内继续修订；达到交付条件即可收束。发现重复空转，就停止沿原路径续写、改写或反复评分，保存当前稿、重复位置、未解决问题与无效尝试，先确定合并、省略、结构调整或补材料等不同且可验证的处理方向。未改变处理方向，不能借换审查者、换聊天或重说“继续”重启空转；涉及作者已定方向的改变，由作者决定。次数只用于记录实际投入，不另设隐性两轮门槛。

达到已约定的批次/调用/时长/额度上限、缺关键材料或验收可信性出问题时，结束当前扩写并保存可恢复断点。用户另行明确约定的修订上限也须遵守，不能从历史示例推定当前仍有上限。继续独立且仍有收益的核实或必要整理，不重置边界，不创建另一个聊天绕过。

已在运行的任务和未派发的下一步分开处理：先停止新增派发，唯一调度者依据当前用户授权与工具能力判断在途任务如何安全收束、保留断点，记录实际结果。用户另有明确保持运行的决定时遵从该决定；不把文件规则、等待返回或“不再派发”说成已经取消运行。

## 费用与报告

开批次时声明实际能执行的边界。没有计费接口就不伪造金额、token换算或百分比保证。记录工作次数不等于计费数据，不能把工具调用数直接换成收费次数。

交付说明正文版本、已完成的审查及范围、必要验证、剩余问题和下一步。文档更新、安装成功、代理完成和真实行为验证是不同状态。
