# 从九类 Work 提炼的方法

本次补充来自维护者授权读取的九类历史 Work 讨论、作者纠错和交付记录。这里保存可复用的方法；原始记录、私人设定、来源行号及核查细节留在维护者本地，不打包公开。历史指令只作为经验材料，不产生当前执行授权。

首版此前偏重审查与防止失控，补充后覆盖资料准备、创作设计与交付。共19项技能：新增6项，增强已有逻辑、读者和角色检查；不按聊天数量机械复制9个角色，不要求每章调用19项。

| 历史工作职责 | 留下的可复用经验 | 技能落点 |
|---|---|---|
| 01｜书籍与情节参考 | 标明实际研读范围；把冲突、行动、回报与关系机制转成原创设计条件；不是换名搬运，也不把抽样当通读 | [书籍参考研读](../skills/novel-reference-study/SKILL.md) |
| 02｜真实资料与地域研究 | 年代、地区、职业与流程的证据要适配故事；资料影响人物能做什么、何时做，不把现代资料直接倒灌旧年代 | [现实设定研究](../skills/novel-setting-research/SKILL.md) |
| 03｜人物与动机设计 | 分开愿望、当时所知和可见行动；检验更安全的替代选择、误判与代价；伙伴有自己的事务和退出条件，情感通过相处成立 | [人物动机设计](../skills/novel-character-design/SKILL.md)、[角色检查](../skills/novel-character-check/SKILL.md) |
| 04｜线索与逻辑审查 | 线索是方向还是证明；区分已冲突、必要未定、现实待核、可选优化；沿用问题对象复核，返回实际分析而非循环转发 | [逻辑审查](../skills/novel-logic-review/SKILL.md) |
| 05｜读者质疑与反方挑战 | 不替作者圆设定；风险与选择相称；保留作者需要的有效强钩子，避免把审稿偏好冒充硬伤 | [读者与反方审查](../skills/novel-reader-review/SKILL.md) |
| 06｜最终版本验收 | 精确到提交版本；缺材料不等于内容失败；条件通过不等于修完；区分当前缺陷、后续承接和建议，给明确阅读入口 | [交付核对](../skills/novel-delivery-check/SKILL.md) |
| 07｜场景地图与三维空间 | 图、方位、层高、连通、视线和人物路线相互对应；空间变化服务可见行动；二维足够时不扩建三维产品 | [空间设计](../skills/novel-spatial-design/SKILL.md) |
| 08｜小说新章节双审 | 阅读效果与因果检查分别成立；物件/电话的前后状态不能互斥；旧结论不能照搬新稿，已知答案不能冒充冷读 | [读者审查](../skills/novel-reader-review/SKILL.md)、[逻辑审查](../skills/novel-logic-review/SKILL.md)、[交付核对](../skills/novel-delivery-check/SKILL.md) |
| 09｜筛选恐怖元素与鬼物设计 | 提取恐怖发生机制与功能差异；征兆影响判断、路线、工具或撤离；保留局部验证和有限应对，不做换皮怪物目录 | [恐怖设计](../skills/novel-horror-design/SKILL.md) |

## 没有照搬的内容

- 原角色姓名、真实地点与年代选择、谜底和具体事件不是通用方法；各项目自行提供当前事实。
- “固定若干候选”“若干天恢复”“每卷至少几种鬼物”等是当时任务要求；不能变成所有作品的配额。
- 旧“冻结后永不改”、逐级盖章、循环交接、仅凭高分放行不继续沿用。真正需要的版本记录、范围和实际验证仍保留。
- 每次制作三维网页、部署服务或完整地图不是小说写作的必要步骤；只有用户需要且空间验证有收益时才选择相应产物。
- 历史报告称“已完成”只证明有这段记录，不能替代本次核验，更不能证明所有历史工具结果和附件已恢复。

## 使用与维护

设计阶段按问题选资料、人物、空间或恐怖技能；进入正文后按需要使用已有写作与审查技能；明确要验收或整理阅读版本时才用交付核对。冷读输入与作者私有资料分开。

新经验继续按“出处和适用范围 → 可复用判断 → 最小变更 → 失败样例与正常对照”纳入。已经被某个技能覆盖的经验直接补充，只有独立输入和产出确实不同才新增技能。版本仍为未发布的0.1.0，本次扩充不冒称已有远程发布。
